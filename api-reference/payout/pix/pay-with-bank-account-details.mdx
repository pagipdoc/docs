## Behavior and handling

Initiate a Pix payment directly using the payee's bank account details, without Pix key or QR code initialization. The payer and payee must not have the same ISPB and account number; that combination is rejected with code `400` and message "Payer and payee bank accounts must be different". <Badge color="blue" size="sm">Added · api-12-F20</Badge> Verify the payee, amount, and account funding requirements before submitting. Keep enough available balance to cover the total amount debited for the payment. The balance block is performed during asynchronous processing; a successful submission can still later fail for insufficient available balance. Confirm the final outcome through the payment status or details. <Badge color="blue" size="sm">Added · api-12-F21</Badge>

Payments are subject to the payer account's configured transaction limits and risk controls. A limit rejection can return code `4001998`; a risk-control rejection can return code `4003016`. These limits are account-specific, not a fixed maximum defined by this endpoint. Use the actual code and message to investigate the rejection. <Badge color="blue" size="sm">Added · api-12-F23</Badge>

If the request result is unknown, check the original transaction as described in [Error scenarios in the outgoing payment module](/api-reference/payout/overview). Do not resend the request directly.

## Permissions and account ownership

Use `ACCOUNT` credentials for their bound payer account, or `USER` credentials with both `X-ISPB` and `X-Account-Number` selecting a payer account owned by that `USER`. The selected account and its required parent-account hierarchy must be active. `PLATFORM` credentials are not accepted. With `ACCOUNT` credentials, omit both account-target headers or send both with values exactly matching the credential binding; one missing, empty, or mismatched target header is rejected. <Badge color="blue" size="sm">Added · api-12-F22</Badge> Requests must follow [Environments & Credentials](/environments-and-credentials).

## Request parameters

<ParamField body="payee" type="object" required>
Payee identity and bank account information
</ParamField>

<ParamField body="payee.name" type="string" required>
↳ Payee name
</ParamField>

<ParamField body="payee.document_id" type="string" required>
↳ Payee document ID, consistent with the document type and the actual payee account. Provide an unformatted CPF with 11 digits, or a CNPJ with 14 characters: 12 uppercase letters or digits followed by 2 digits. Document-format validation also occurs during payment processing, so API acceptance does not prove that the payment will complete <Badge color="blue" size="sm">Added · api-12-F09</Badge>
</ParamField>

<ParamField body="payee.document_type" type="integer">
↳ **Required:** Yes <Badge color="orange" size="sm">Corrected · api-12-F01</Badge> Use `1 CPF` or `2 CNPJ`, matching the payee's document. `0 UNSPECIFIED` and all other values are rejected <Badge color="orange" size="sm">Corrected · api-12-F02</Badge>
</ParamField>

<ParamField body="payee.bank_account" type="string" required>
↳ Payee account number; preserve leading zeros. Use digits only, with no spaces, letters, hyphens, or other punctuation <Badge color="blue" size="sm">Added · api-12-F07</Badge>
</ParamField>

<ParamField body="payee.bank_account_type" type="integer">
↳ **Required:** Yes <Badge color="orange" size="sm">Corrected · api-12-F03</Badge> Use `1 CHECKING`, `2 SALARY`, `3 SAVINGS`, or `4 PAYMENT`, matching the actual payee account. `0 UNSPECIFIED`, `5 TRANSCTIONAL_PI`, `6 GUARANTEED`, `7 DEPOSIT`, and all other values are rejected <Badge color="orange" size="sm">Corrected · api-12-F04</Badge>
</ParamField>

<ParamField body="payee.bank_branch" type="string" required>
↳ Payee bank branch code; preserve leading zeros. Use digits only, with no spaces, letters, hyphens, or other punctuation <Badge color="blue" size="sm">Added · api-12-F08</Badge>
</ParamField>

<ParamField body="payee.bank_code" type="string" required>
↳ Payee bank ISPB string; preserve leading zeros. Open API removes all whitespace, converts letters to uppercase, and pads values shorter than 8 characters with leading zeros. After normalization, the value must contain exactly 8 uppercase letters or digits. The current transaction service further restricts this to digits only. Provide an actual, valid 8-digit ISPB
</ParamField>

<ParamField body="payee.bank_name" type="string">
↳ **Required:** No <Badge color="orange" size="sm">Corrected · api-12-F05</Badge> Optional bank name. This endpoint ignores the supplied value; `payee.bank_code` determines the bank used for the payment <Badge color="orange" size="sm">Corrected · api-12-F06</Badge>
</ParamField>

<ParamField body="amount" type="string" required>
Decimal amount string; the value must be greater than `0` and exactly representable with two decimal places (for example, `10.00`). Extra trailing zeros, such as `10.000`, are accepted; `0`, negative numbers, and `10.555` are not accepted <Badge color="orange" size="sm">Corrected · api-12-F10</Badge>
</ParamField>

<ParamField body="currency" type="string">
**Required:** No (not enforced at this layer). Currency; bank account payments are processed in `BRL` in this version. The supplied value is ignored and does not change the payment currency; use `BRL` or omit the field <Badge color="blue" size="sm">Added · api-12-F11</Badge>
</ParamField>

<ParamField body="memo" type="string">
**Required:** No (not enforced at this layer). Transaction note
</ParamField>

<ParamField body="merchant_order_id" type="string" required>
Merchant order ID; only English letters, digits, hyphens, and underscores are allowed. The first six characters must be a valid `YYMMDD` UTC date. The date must overlap the window within ±1 hour of the current UTC time. Use an ID unique across your integrations in the same environment, not only within one payer account. Duplicate protection retains a reserved ID for 48 hours; a repeated reserved ID is rejected with code `4001013` and does not return the original success response. If the result is unknown, query the original operation first. Do not blindly resubmit with a new ID <Badge color="blue" size="sm">Added · api-12-F12</Badge>
</ParamField>
