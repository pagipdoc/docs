## Funcionamento e tratamento

Consulte os dados pelo ID do QR Code e confira a associação entre o QR Code e o pedido do comerciante. Este endpoint não substitui a consulta à transação de recebimento.

## Permissões e titularidade da conta

Use credenciais `ACCOUNT` para a conta vinculada, ou credenciais `USER` com `X-ISPB` e `X-Account-Number` para uma conta autorizada pertencente a esse `USER`. Credenciais `PLATFORM` não são aceitas. Com credenciais `ACCOUNT`, omita os dois headers de conta ou envie ambos com valores correspondentes à conta vinculada. O QR Code deve pertencer à conta selecionada; caso contrário, a resposta retorna o code de negócio `4004004` com a mensagem `QR code not found`. As requisições devem seguir as orientações de [Ambientes e credenciais](/pt-br/environments-and-credentials). <Badge color="blue" size="sm">Complementado · api-3-F02</Badge>

## Parâmetros da requisição

<ParamField body="qr_code_id" type="string" required>
ID do QR Code; obtido em `data.qr_code_id` na resposta de geração do QR Code. Use o ID sem alterações e sem espaços nas extremidades. Ele deve conter 25 ou 26 caracteres: um prefixo de oito dígitos com data e hora UTC válidas no formato `YYMMDDHH`, seguido de 17 ou 18 caracteres hexadecimais (0–9, a–f ou A–F). <Badge color="blue" size="sm">Complementado · api-3-F01</Badge>
</ParamField>

<Info>
**Origem dos parâmetros**

O campo `qr_code_id` deve conter o ID de um QR Code existente. Primeiro, chame [Gerar QR Code dinâmico](/pt-br/api-reference/payin/generate-dynamic-qr-code) ou [Gerar QR Code estático](/pt-br/api-reference/payin/generate-static-qr-code). Depois, copie `data.qr_code_id` da resposta.
</Info>

## Respostas

Consulte os exemplos de resposta pelo `code` de negócio no JSON. Verifique o status HTTP e o code de negócio separadamente. <Badge color="orange" size="sm">Corrigido · api-3-F04</Badge>

Uma resposta HTTP 200 também pode retornar um erro de negócio. Se o corpo não puder ser decodificado como JSON, inclusive por um tipo de campo incompatível, a requisição poderá retornar HTTP 400 com um erro em texto simples; não presuma que todo corpo de erro seja JSON. <Badge color="blue" size="sm">Complementado · api-3-F07</Badge>

| `code` | Significado | Ação recomendada |
| --- | --- | --- |
| `200` | Requisição bem-sucedida | Leia data e avalie o resultado do processamento conforme o status de negócio deste endpoint. |
| `400` | Falha na requisição ou validação | Problema nos parâmetros. Verifique e corrija os parâmetros da requisição. |
| `500` | Erro do sistema | Registre a resposta e confirme primeiro o resultado de negócio. |

Os exemplos ilustram a estrutura da resposta. Os valores de `message` e do status de negócio devem ser obtidos da resposta efetiva. Para outros erros de parâmetros, permissões e serviço, consulte [Catálogo de erros](/pt-br/api-reference/error-catalog). Esta seção não indica que o endpoint retorna apenas os três valores de `code` apresentados. Neste endpoint, `qr_code_id` ausente ou vazio retorna `4000` (`Field qr_code_id is required`); um ID de QR Code com formato inválido retorna `400` (`qr_code_id is invalid`); e um QR Code inexistente ou que não pertence à conta selecionada retorna `4004004` (`QR code not found`). Uma falha na consulta do QR Code ou da transação associada pode retornar `4003014`, com uma mensagem que identifica a consulta que falhou. Uma conexão temporariamente indisponível pode retornar `501`. As mensagens podem depender do idioma da resposta; use o valor real de `message`. <Badge color="blue" size="sm">Complementado · api-3-F06</Badge>

## Exemplo de acesso ao Sandbox

Considere a resposta real como referência para os dados da transação ou do recurso, o status do processamento e as informações de erro.

`X-Client-ID` usa a AK informada. O timestamp, o nonce, o hash do corpo da requisição e a assinatura são gerados automaticamente. A SK é usada apenas para assinar localmente, não é enviada na requisição nem armazenada. A visualização não envia a requisição; o botão de acesso envia uma requisição real. Se o resultado for desconhecido, consulte antes de tentar novamente. Não há novas tentativas automáticas. O acesso pelo navegador deve atender aos requisitos de CORS, IP e credenciais do Sandbox.
