## Behavior and handling

Deactivate the subscription for the authenticated owner. With `ACCOUNT` credentials, the subscription belongs to the bound account. With `USER` credentials, transaction subscriptions are shared at the user and application level for each event type; `account_number` is required in the request but does not restrict deactivation to that account. Deactivating a `USER` subscription therefore affects that shared subscription, not only the named account. <Badge color="orange" size="sm">Corrected · api-30-F03</Badge> After submitting the request, query the configuration to confirm deactivation.

## Permissions and account ownership

Authorization depends on the subscription owner identity and scope. `ACCOUNT` credentials use the bound account and cannot deactivate `MASTER_ACCOUNT_KYB` subscriptions. `USER` credentials support transaction events `1`–`4`, which require `account_number`, and `VA_ACCOUNT_KYB` (`5`), for which `account_number` must be omitted or empty. `PLATFORM` credentials support only `MASTER_ACCOUNT_KYB` (`6`), and `account_number` must be omitted or empty. Subscriptions belonging to a different account, user, or platform tenant cannot be accessed. <Badge color="blue" size="sm">Added · api-30-F02</Badge> See [Webhooks](/api-reference/webhooks/overview). Requests must follow [Environments & Credentials](/environments-and-credentials).

## Request parameters

<ParamField body="event_type" type="integer" required>
Webhook event types: `1` `PIX_IN`; `2` `PIX_OUT`; `3` `REFUND_IN`; `4` `REFUND_OUT`; `5` `VA_ACCOUNT_KYB`; `6` `MASTER_ACCOUNT_KYB`. The permitted values depend on credential ownership. A value of `0` is not accepted. <Badge color="blue" size="sm">Added · api-30-F01</Badge>
</ParamField>

<ParamField body="account_number" type="string">
**Required:** Conditionally required. Trim leading and trailing whitespace first. Preserve leading zeros. Optional for ACCOUNT credentials. If provided, the value must match the bound account number. Required when USER credentials subscribe to transaction events.
</ParamField>

<ParamField body="subscription_id" type="string">
Trim leading and trailing whitespace. If provided, `subscription_id` selects the subscription by ID, with ownership checked against the authenticated account, user, or platform tenant. Application and event type are not additional matching filters for a supplied ID, and `USER` `account_number` does not narrow the selection. If omitted, selection uses the authenticated owner, application, and event type; `ACCOUNT` selection also uses the bound ISPB and account number. Use the ID of the subscription you intend to deactivate. You must not access another owner's subscription. <Badge color="orange" size="sm">Corrected · api-30-F04</Badge>
</ParamField>

## Response fields

Field paths start at the response root. `[]` indicates an array element. Amounts use decimal strings. Enum values are defined separately for each field. The structure below describes a success response. A null value or 0 alone does not indicate that processing is complete.

<ResponseField name="code" type="integer">
Business result code. A value of 200 indicates success. Business errors are returned in this field. It is not the HTTP status code.
</ResponseField>

<ResponseField name="message" type="string">
Business result description. On failure, use this with code to determine the cause.
</ResponseField>

<ResponseField name="data" type="object">
Data object in a successful response. Can be null in an error response.
</ResponseField>

<ResponseField name="time" type="integer">
Response time as a UTC Unix timestamp in milliseconds.
</ResponseField>

<ResponseField name="data.webhook_id" type="string">
Event subscription ID.
</ResponseField>

<ResponseField name="data.deleted_at" type="integer">
Time when the successful deactivation response is produced, in UTC Unix milliseconds. Populated on success. The subscription is deactivated, not deleted; this value is not a stored deletion timestamp. <Badge color="orange" size="sm">Corrected · api-30-F05</Badge>
</ResponseField>

## Responses

View response examples by the business `code` in the JSON response. Invalid JSON or a request-body read failure can return HTTP `400` with a plain-text error instead of this JSON structure. Handle non-JSON responses separately from business errors. <Badge color="blue" size="sm">Added · api-30-F10</Badge> Check the HTTP status and business code separately. An HTTP 200 response can also return a business error. <Badge color="orange" size="sm">Corrected · api-30-F06</Badge>

| `code` | Meaning | Recommended action |
| --- | --- | --- |
| `200` | Request succeeded | A business code of `200` confirms that the subscription was deactivated. This response has no subscription-status field. Query the subscription configuration and confirm status `2` (`BASE_STATUS_INACTIVE`). The subscription ID remains unchanged. <Badge color="orange" size="sm">Corrected · api-30-F07</Badge> |
| `400` | Request or validation failed | Parameter issue. Check and correct the request parameters. |
| `500` | System error | Log the response and confirm the business result first. |

The examples illustrate the response structure. Use the actual response for message and business status values. See [Error Catalog](/api-reference/error-catalog) for other parameter, permission, and service errors. This section does not imply that the endpoint returns only these three code values. Common errors for this endpoint include code `4000` when `event_type` is omitted or `0`, or when `USER` transaction events omit `account_number`; code `4004003` when credential ownership or the event/account combination is not permitted; code `4004004` when the subscription is not found; and code `501` when the subscription operation cannot reach the required service. Correct parameter or permission issues before retrying. For an unknown deactivation result, query the subscription configuration first. <Badge color="blue" size="sm">Added · api-30-F11</Badge>
