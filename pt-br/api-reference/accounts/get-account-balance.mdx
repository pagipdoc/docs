## Funcionamento e tratamento

Use credenciais de nível ACCOUNT para consultar os dados, o saldo, o valor bloqueado e as configurações da própria conta vinculada às credenciais.

Se a consulta do snapshot do saldo falhar, o campo code no nível externo ainda poderá ser 200, e os valores monetários terão 0 como fallback. A resposta atual não contém indicador de fallback. Uma única resposta não permite distinguir um saldo realmente zerado de um valor de fallback. Consulte novamente e confira os detalhes das transações e os lançamentos do extrato da conta. Se os resultados continuarem divergentes, guarde os dados da conta, o horário da consulta e a resposta com dados sensíveis mascarados e entre em contato com o suporte de integração para verificação.

## Permissões e titularidade da conta

Use a AK/SK de nível ACCOUNT da conta. Por padrão, a consulta usa a conta vinculada às credenciais, sem necessidade de informar headers de conta. Se forem informados, `X-ISPB` e `X-Account-Number` devem ser preenchidos juntos e corresponder à conta vinculada.

O corpo da requisição é `{}`. A seleção da conta não é enviada pelo campo `account_number` no corpo da requisição. Para a assinatura da requisição, consulte [Ambientes e credenciais](/pt-br/environments-and-credentials).

## Campos da resposta

Os caminhos dos campos partem da raiz da resposta. `[]` indica um elemento de array. Os valores monetários usam strings decimais. Os enums são interpretados conforme cada campo. A estrutura abaixo representa os dados de uma resposta de sucesso. Um valor nulo ou 0, por si só, não indica a conclusão da operação.

## Respostas

Consulte os exemplos de resposta pelo `code` de negócio no JSON. JSON malformado é rejeitado com HTTP 400 e um erro em texto simples, em vez deste envelope JSON. Uma falha do sistema tratada também pode retornar HTTP 500 com uma resposta em texto simples. <Badge color="blue" size="sm">Complementado · api-23-F17</Badge> Verifique o status HTTP e o code de negócio separadamente. Uma resposta HTTP 200 também pode retornar um erro de negócio.

| `code` | Significado | Ação recomendada |
| --- | --- | --- |
| `200` | Requisição bem-sucedida<br />O exemplo a seguir ilustra a estrutura. Os números de conta, valores e horários são demonstrativos. Listas vazias indicam que o exemplo não apresenta configurações específicas. As duas consultas retornam a mesma estrutura. `account_number` e `ispb` identificam a conta consultada. | Verifique os campos externos `code` e `message` e leia `data` como um snapshot da conta. Este endpoint não possui um campo de status de processamento da consulta. Um `code` igual a `200` não descarta os valores de fallback descritos acima. <Badge color="orange" size="sm">Corrigido · api-23-F16</Badge> |
| `400` | Falha na requisição ou validação | Problema nos parâmetros. Verifique e corrija os parâmetros da requisição. |
| `500` | Erro do sistema | Registre a resposta e confirme primeiro o resultado de negócio. |

Os exemplos ilustram a estrutura da resposta. Os valores de message e do status de negócio devem ser obtidos da resposta efetiva. Para outros erros de parâmetros, permissões e serviço, consulte [Catálogo de erros](/pt-br/api-reference/error-catalog). Esta seção não indica que o endpoint retorna apenas os três valores de code apresentados. <Badge color="orange" size="sm">Corrigido · api-23-F15</Badge>

<Tip>
Para testar este endpoint, envie o exemplo de requisição para a Base URL do Sandbox `https://ebanking-openapi-sandbox.pagsmile.com.br` com sua AK/SK de Sandbox. Assine cada requisição conforme descrito em [Ambientes e credenciais](/pt-br/environments-and-credentials#assinatura-de-requisições-à-api).
</Tip>
