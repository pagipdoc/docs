## Funcionamento e tratamento

Inicie uma devolução referente ao recebimento Pix original para devolver os recursos ao pagador original. A devolução é iniciada pelo recebedor original, com as credenciais da conta do recebedor original. <Badge color="orange" size="sm">Corrigido · api-5-F17</Badge> Após a aceitação da requisição, salve os IDs da devolução, continue consultando o resultado e confira os lançamentos da devolução no extrato. A aceitação retorna `PENDING` antes do bloqueio dos recursos para a devolução. Por isso, saldo disponível insuficiente pode causar a falha da devolução durante o processamento posterior. <Badge color="blue" size="sm">Complementado · api-5-F13</Badge> Para transições de status e tratamento de erros, veja [Devoluções](/pt-br/api-reference/refunds/overview).

### Verificações antes de iniciar

| Condições | Requisitos |
| --- | --- |
| Transação original | A transação original deve ser um pagamento Pix concluído, com valor restante disponível para devolução maior que zero, e a conta-alvo deve ser a do recebedor original. Use o `settlement_id` desse pagamento no lançamento correspondente do extrato da conta com `is_credit=true` <Badge color="blue" size="sm">Complementado · api-5-F09</Badge> |
| Prazo para devolução | O código local atual valida o prazo somando 90 dias ao initiated_at da transação original e rejeita requisições após esse prazo. Em produção, prevalece a versão efetivamente implantada |
| Valor | Maior que 0, com um valor exatamente representável com duas casas decimais, sem exceder o valor restante disponível para devolução da transação original; zeros adicionais ao final da parte decimal são aceitos. Salve um registro separado para cada devolução parcial <Badge color="orange" size="sm">Corrigido · api-5-F03</Badge> |
| Conta | A conta do recebedor original deve ser a mesma que inicia a devolução e atender aos requisitos de status da conta e de recursos |
| ID do pedido | Preencha conforme as regras de data UTC e de formato da tabela de parâmetros. Para tratamento de erros, veja o módulo [Devoluções](/pt-br/api-reference/refunds/overview) |

O valor restante disponível para devolução é o valor original menos os valores já devolvidos, os valores retornados por chargebacks e os valores reservados para devoluções pendentes. Um resultado negativo é considerado zero. <Badge color="blue" size="sm">Complementado · api-5-F10</Badge>

## Permissões e titularidade da conta

Use credenciais `ACCOUNT` da conta do recebedor original ou credenciais `USER` com os headers `X-ISPB` e `X-Account-Number`, selecionando uma conta pertencente a esse `USER`. Credenciais `ACCOUNT` não podem selecionar outra conta; se os headers da conta forem enviados, ambos devem estar preenchidos e corresponder à conta da credencial. Credenciais `PLATFORM` não são aceitas. <Badge color="blue" size="sm">Complementado · api-5-F08</Badge> As requisições devem seguir as orientações de [Ambientes e credenciais](/pt-br/environments-and-credentials).

## Parâmetros da requisição

<ParamField body="original_settlement_id" type="string" required>
ID de liquidação do recebimento Pix original que será devolvido; obtenha-o em `data.details.settlement_id` de [Consultar detalhes da transação](/pt-br/api-reference/payin/get-transaction-details) ou no lançamento de crédito correspondente em [Consultar extrato da conta](/pt-br/api-reference/accounts/get-account-statement) <Badge color="orange" size="sm">Corrigido · api-5-F01</Badge>
</ParamField>

<ParamField body="merchant_order_id" type="string" required>
ID do pedido do comerciante; permite apenas letras do alfabeto inglês, números, hífens e sublinhados. Os primeiros seis caracteres devem formar uma data UTC válida no formato YYMMDD. A data deve ter interseção com a janela de ±1 hora em relação ao horário UTC atual. Se o resultado for desconhecido, consulte primeiro a operação original. Não reenvie com outro ID sem essa verificação
</ParamField>

Use um ID de pedido único entre contas e operações no mesmo ambiente. IDs duplicados são retidos por 48 horas e rejeitados com o code de negócio `4001013`; o endpoint não retorna novamente a resposta de sucesso original. Um erro de duplicidade não comprova que a devolução original falhou. Mantenha o ID de pedido original e verifique a operação existente antes de tentar novamente. <Badge color="blue" size="sm">Complementado · api-5-F11</Badge>

<ParamField body="amount" type="string" required>
String com o valor decimal; o valor deve ser maior que 0 e exatamente representável com duas casas decimais (por exemplo, `10.00`). Zeros adicionais ao final da parte decimal, como em `10.000`, são aceitos; não são aceitos `0`, números negativos ou `10.555` <Badge color="orange" size="sm">Corrigido · api-5-F04</Badge>
</ParamField>

<ParamField body="reason" type="string">
**Obrigatório:** Não (não obrigatório nesta camada). Texto explicativo opcional da devolução. Este campo não seleciona o código do motivo da devolução Pix; este endpoint inicia uma devolução solicitada pelo recebedor usando `MD06`. Se omitido, o texto explicativo fica vazio <Badge color="blue" size="sm">Complementado · api-5-F12</Badge>
</ParamField>

<Info>
**Origem dos parâmetros**

Selecione o lançamento do extrato correspondente ao recebimento Pix original específico que será devolvido. Use o `settlement_id` desse lançamento na resposta de sucesso de [Consultar extrato da conta ↗](/pt-br/api-reference/accounts/get-account-statement) (`/v3/statements`) e confirme que `is_credit=true` e que o ID de liquidação é válido. Não selecione automaticamente o primeiro lançamento de crédito. <Badge color="orange" size="sm">Corrigido · api-5-F02</Badge>
</Info>

## Campos da resposta

Os caminhos dos campos partem da raiz da resposta. `[]` indica um elemento de array. Os valores monetários usam strings decimais. Os enums são interpretados conforme cada campo. A estrutura abaixo representa os dados de uma resposta de sucesso. Um valor nulo ou 0, por si só, não indica a conclusão da operação.

<ResponseField name="code" type="integer">
Código de resultado de negócio; 200 indica sucesso. Os erros de negócio são retornados neste campo, que não equivale ao código de status HTTP.
</ResponseField>

<ResponseField name="message" type="string">
Descrição do resultado de negócio; em caso de falha, analise esta descrição junto com o campo code para identificar a causa.
</ResponseField>

<ResponseField name="data" type="object">
Objeto de dados da resposta de sucesso; pode ser null em respostas de erro.
</ResponseField>

<ResponseField name="time" type="integer">
Horário da resposta, em timestamp Unix UTC em milissegundos.
</ResponseField>

<ResponseField name="data.settlement_refund_id" type="string">
ID de liquidação da devolução.
</ResponseField>

<ResponseField name="data.refund_id" type="string">
ID da devolução; usado para consultar os detalhes ou o status da devolução.
</ResponseField>

<ResponseField name="data.merchant_order_id" type="string">
ID do pedido do comerciante fornecido pelo chamador; atualmente não é preenchido na resposta de criação da devolução e retorna como uma string vazia.
</ResponseField>

<ResponseField name="data.txn_status" type="integer">
Status da transação. Uma requisição de criação aceita retorna `1` `TXN_STATUS_PENDING`; o processamento é assíncrono. Consulte o status da devolução para determinar o resultado final. Enum: `0` `TXN_STATUS_UNSPECIFIED`; `1` `TXN_STATUS_PENDING`; `2` `TXN_STATUS_COMPLETED`; `3` `TXN_STATUS_FAILED`; `4` `TXN_STATUS_CANCELLED`; `5` `TXN_STATUS_PROCESSING`; `6` `TXN_STATUS_REFUNDED`; `7` `TXN_STATUS_PARTIALLY_REFUNDED`; `8` `TXN_STATUS_DISPUTED`. <Badge color="blue" size="sm">Complementado · api-5-F07</Badge>
</ResponseField>

## Respostas

Consulte os exemplos de resposta pelo `code` de negócio no JSON. Verifique o status HTTP e o code de negócio separadamente. Uma resposta HTTP 200 também pode retornar um erro de negócio. <Badge color="orange" size="sm">Corrigido · api-5-F06</Badge>

| `code` | Significado | Ação recomendada |
| --- | --- | --- |
| `200` | Requisição bem-sucedida | Leia data e avalie o resultado do processamento conforme o status de negócio deste endpoint. |
| `400` | Falha na requisição ou validação | Problema nos parâmetros. Verifique e corrija os parâmetros da requisição. |
| `500` | Erro do sistema | Registre a resposta e confirme primeiro o resultado de negócio. |

Os exemplos ilustram a estrutura da resposta. Os valores de message e do status de negócio devem ser obtidos da resposta efetiva. Para outros erros de parâmetros, permissões e serviço, consulte [Catálogo de erros](/pt-br/api-reference/error-catalog). Esta seção não indica que o endpoint retorna apenas os três valores de code apresentados. Erros relevantes incluem `4000` quando falta `original_settlement_id`, `merchant_order_id` ou `amount`; `4002` para formato inválido do valor; `400` para regras inválidas do ID do pedido, transação original inelegível, conta bloqueada ou prazo de devolução expirado; `4001013` para ID de pedido duplicado; `4003003` quando a transação original não é encontrada; `4003005` quando o valor excede o valor restante disponível para devolução; `4004101` quando a conta que inicia a devolução não corresponde à do recebedor original; `4003016` para rejeição por controles de risco; e `501` para indisponibilidade temporária da API. Leia o `message` efetivo junto com o `code` para distinguir a causa. <Badge color="blue" size="sm">Complementado · api-5-F16</Badge>

</Tip>
