## Response evaluation

Record the HTTP status and the JSON business code separately. When you receive a normal JSON response, the outer `code=200` means the API request succeeded. Other code values indicate failure. HTTP 200 alone does not indicate business success. Check the final status of payments, refunds, and account opening through the appropriate endpoints. Use `message` for display or troubleshooting, not as a stable condition for programmatic decisions.

| Scenario | Action |
| --- | --- |
| HTTP 200, outer code=200 | Read data and check the business status |
| HTTP 200, outer code is not 200 | Handle the business error using the codes below |
| Non-JSON or plain-text error | Handle response format and transport errors separately |
| Timeout or dropped connection | Unknown result. Query the original operation first |

## Success

| code | Meaning | What to check |
| --- | --- | --- |
| `200` | Success | Read data. Check the completion status as specified for the endpoint. |

| `4001011 / 4001012` | Request expired/invalid time range | Check the request time and allowed range. |

## Authentication and permissions

| code | Meaning | What to check |
| --- | --- | --- |
| `4003008` | Authentication required | Check the endpoint authentication and target account. |
| `4004003` | Insufficient permissions/MED return capability unavailable | Check permissions for the endpoint. For MED, also check the return capability. If a payout is restricted because of MED recovery, check the MED status and the account's available balance. <Badge color="blue" size="sm">Added · error-catalog-F11</Badge> |
| `4004101` | Authorization is required | Check the identity associated with the credentials. |
| `4004102` | Invalid header or request metadata | Check the required headers and their format. |
| `4004103` | Source IP is not on the allowlist | Verify the outbound IP configuration. |
| `4004104` | Request body hash does not match | Compute the hash from the raw bytes actually sent. |
| `4004105` | Timestamp is invalid or expired | Use Unix milliseconds and synchronize your clock. The official documentation specifies an acceptance window of 5 minutes. |
| `4004106` | Nonce is invalid or already used | Generate a new nonce for each request, including retries after authentication failures. Nonces are tracked separately for each AK for 10 minutes and can be consumed even when the signature or permissions are rejected. <Badge color="blue" size="sm">Added · error-catalog-F06</Badge> |
| `4004107` | Signature does not match | Check the SK, string to sign, and raw request. |
| `401` | Invalid user | Check the user and credentials context. |
| `4010 / 4011 / 4012` | Authentication failed/invalid token/expired token | Check authentication for the endpoint. These names do not indicate that v3 supports OAuth. v3 still uses HMAC signatures. |

## Rate limiting and service status

| code | Meaning | What to check |
| --- | --- | --- |
| `4004029` | Too many requests | Reduce the request rate and decide whether to retry based on the endpoint's conditions. |
| `500` | System error | Log the response and confirm the business result first. |
| `501 / 502 / 503` | Service unavailable/bank busy/not currently supported | Check the service status and the result of the original operation. |
| `504` | Compliance verification temporarily unavailable | For managed account creation, the compliance submission result could not be confirmed and the account creation fee was not charged. Retry with the same `reference_id` and regenerate the signature information. Do not add `request_id` to this request. <Badge color="orange" size="sm">Corrected · error-catalog-F01</Badge> |

## Retries and troubleshooting

First, correct the parameters, signature, permissions, or account conditions. After a timeout, duplicate request, or payment failure, query the original operation before deciding whether to resubmit. You must not resend with a different order ID solely because no response was received. For technical retries, follow the endpoint's rules for business identifiers. Regenerate the timestamp, nonce, and request body hash each time you sign.

If you encounter an unknown error code, record the environment, endpoint path, request time, HTTP status, code, message, resource identifier, and masked response. Contact integration support.
