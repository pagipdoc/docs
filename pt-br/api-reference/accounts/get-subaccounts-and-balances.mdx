## Funcionamento e tratamento

Use credenciais de nível USER para consultar os dados, o saldo, o valor bloqueado e as configurações de uma subconta dentro do escopo de autorização. Cada consulta abrange apenas uma conta-alvo.

Se a consulta do snapshot do saldo falhar, o campo code no nível externo ainda poderá ser 200, e os valores monetários terão 0 como fallback. A resposta atual não contém indicador de fallback. Uma única resposta não permite distinguir um saldo realmente zerado de um valor de fallback. Consulte novamente e confira os detalhes das transações e os lançamentos do extrato da conta. Se os resultados continuarem divergentes, guarde os dados da conta, o horário da consulta e a resposta com dados sensíveis mascarados e entre em contato com o suporte de integração para verificação.

## Permissões e titularidade da conta

Use AK/SK de nível USER. É obrigatório enviar os dois headers da subconta-alvo: `X-ISPB` e `X-Account-Number`. O servidor valida o status da conta-alvo e seu vínculo com o USER. Não é permitido consultar contas de outros usuários.

O corpo da requisição é `{}`. A seleção da conta não é enviada pelo campo `account_number` no corpo da requisição. Para a assinatura da requisição, consulte [Ambientes e credenciais](/pt-br/environments-and-credentials).

## Parâmetros da requisição

<ParamField header="X-Client-ID" type="string">
AK de nível USER
</ParamField>

<ParamField header="X-ISPB" type="string">
Obrigatório, ISPB da subconta-alvo, com os zeros à esquerda preservados
</ParamField>

<ParamField header="X-Account-Number" type="string">
Obrigatório, número da subconta-alvo, enviado como string e com os zeros à esquerda preservados
</ParamField>

<ParamField body="Sem campos de negócio" type="string">
`{}`
</ParamField>

## Exemplo de requisição cURL

Use sua AK/SK real de nível USER para gerar o timestamp, o nonce, o hash SHA-256 do corpo e a assinatura antes de enviar a requisição. A SK não deve ser incluída na requisição. Os dois headers da conta-alvo também devem participar do cálculo da assinatura.

## Campos da resposta

Os caminhos dos campos partem da raiz da resposta. `[]` indica um elemento de array. Os valores monetários usam strings decimais. Os enums são interpretados conforme cada campo. A estrutura abaixo representa os dados de uma resposta de sucesso. Um valor nulo ou 0, por si só, não indica a conclusão da operação.

</ResponseField>

<ResponseField name="message" type="string">

## Respostas

Consulte os exemplos de resposta pelo `code` de negócio no JSON. Verifique o status HTTP e o code de negócio separadamente. Uma resposta HTTP 200 também pode retornar um erro de negócio. <Badge color="orange" size="sm">Corrigido · bank-account-child-F10</Badge>

| `code` | Significado | Ação recomendada |
| --- | --- | --- |
| `200` | Requisição bem-sucedida<br />O exemplo a seguir ilustra a estrutura. Os números de conta, valores e horários são demonstrativos. Listas vazias indicam que o exemplo não apresenta configurações específicas. As duas consultas retornam a mesma estrutura. `account_number` e `ispb` identificam a conta consultada. | Quando `code` for `200`, leia os dados da conta. Este endpoint não tem um status separado de processamento da consulta. Interprete os status de chaves Pix e assinaturas de eventos apenas para os respectivos registros e siga as orientações sobre fallback do saldo acima. <Badge color="orange" size="sm">Corrigido · bank-account-child-F11</Badge> |
| `400` | Falha na requisição ou validação | Problema nos parâmetros. Verifique e corrija os parâmetros da requisição. |
| `500` | Erro do sistema | Registre a resposta e confirme primeiro o resultado de negócio. |

Os exemplos ilustram a estrutura da resposta. Os valores de message e do status de negócio devem ser obtidos da resposta efetiva. Para outros erros de parâmetros, permissões e serviço, consulte [Catálogo de erros](/pt-br/api-reference/error-catalog). Esta seção não indica que o endpoint retorna apenas os três valores de code apresentados.

<Tip>
Para testar este endpoint, envie o exemplo de requisição para a Base URL do Sandbox `https://ebanking-openapi-sandbox.pagsmile.com.br` com sua AK/SK de Sandbox. Assine cada requisição conforme descrito em [Ambientes e credenciais](/pt-br/environments-and-credentials#assinatura-de-requisições-à-api).
</Tip>
