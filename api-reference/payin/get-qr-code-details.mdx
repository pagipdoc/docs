## Behavior and handling

Query QR code details by QR code ID to verify the association between the QR code and the merchant order. This endpoint does not replace a query for the actual incoming payment transaction.

## Permissions and account ownership

Use ACCOUNT credentials for the bound account, or USER credentials with both `X-ISPB` and `X-Account-Number` for an authorized account owned by that USER. PLATFORM credentials are not accepted. With ACCOUNT credentials, omit both account headers or supply both with values matching the bound account. The QR code must belong to the selected account; otherwise, the response returns business code `4004004` with message `QR code not found`. Requests must follow [Environments & Credentials](/environments-and-credentials). <Badge color="blue" size="sm">Added · api-3-F02</Badge>

## Request parameters

<ParamField body="qr_code_id" type="string" required>
QR code ID; from `data.qr_code_id` in the QR code generation response. Use the ID unchanged, without surrounding whitespace. It must contain 25 or 26 characters: an eight-digit valid UTC date-and-hour prefix in `YYMMDDHH` format followed by 17 or 18 hexadecimal characters (0–9, a–f, or A–F). <Badge color="blue" size="sm">Added · api-3-F01</Badge>
</ParamField>

<Info>
**Parameter sources**

You must use an existing QR code ID for `qr_code_id`. First call [Generate dynamic QR code](/api-reference/payin/generate-dynamic-qr-code) or [Generate static QR code](/api-reference/payin/generate-static-qr-code), then copy `data.qr_code_id` from the response.
</Info>

## Responses

View response examples by the business `code` in the JSON response. Check the HTTP status and business code separately. An HTTP 200 response can also return a business error. If the body cannot be decoded as JSON, including an incompatible field type, the request can instead return HTTP 400 with a plain-text error; do not assume that every error body is JSON. <Badge color="blue" size="sm">Added · api-3-F07</Badge>

| `code` | Meaning | Recommended action |
| --- | --- | --- |
| `200` | Request succeeded | Read data and determine the result using the business status defined for this endpoint. |
| `400` | Request or validation failed | Parameter issue. Check and correct the request parameters. |
| `500` | System error | Log the response and confirm the business result first. |

The examples illustrate the response structure. <Badge color="orange" size="sm">Corrected · api-3-F04</Badge> Use the actual response for message and business status values. See [Error Catalog](/api-reference/error-catalog) for other parameter, permission, and service errors. This section does not imply that the endpoint returns only these three code values. For this endpoint, a missing or empty `qr_code_id` returns `4000` (`Field qr_code_id is required`); an invalid QR code ID format returns `400` (`qr_code_id is invalid`); and a QR code that does not exist or does not belong to the selected account returns `4004004` (`QR code not found`). A QR code or associated transaction lookup failure can return `4003014` with a message identifying the failed lookup. A temporarily unavailable connection can return `501`. Messages may depend on the response language; use the actual `message`. <Badge color="blue" size="sm">Added · api-3-F06</Badge>
