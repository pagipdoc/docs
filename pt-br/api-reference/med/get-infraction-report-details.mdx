## Funcionamento e tratamento

Consulte os detalhes da notificação de infração indicada. Confira a notificação, o caso e a transação original associados.

## Permissões e titularidade da conta

`ACCOUNT`, ou `USER` com os headers `X-ISPB` e `X-Account-Number` de uma conta pertencente a esse `USER`. Credenciais `PLATFORM` não são aceitas. Credenciais `ACCOUNT` usam a conta vinculada; se os headers da conta-alvo forem enviados, ambos devem estar preenchidos e corresponder a essa conta. A notificação de infração deve estar associada a uma transação recebida pela conta selecionada. <Badge color="blue" size="sm">Complementado · api-22-F05</Badge> As requisições devem seguir as orientações de [Ambientes e credenciais](/pt-br/environments-and-credentials).

## Parâmetros da requisição

<ParamField body="infraction_id" type="string" required>
ID do registro da notificação de infração, obtido em `data.items[].infraction_id` na resposta da listagem. Use esse valor exatamente; ele é diferente de `infraction_report_id` e `dict_infraction_report_id`. <Badge color="blue" size="sm">Complementado · api-22-F06</Badge>
</ParamField>

<Info>
**Origem dos parâmetros**

O `infraction_id` é obtido em `data.items[].infraction_id` na resposta de sucesso de [Listar notificações de infração](/pt-br/api-reference/med/list-infraction-reports) (`/v3/infractions/list`).
</Info>

## Respostas

Consulte os exemplos de resposta pelo `code` de negócio no JSON. Verifique o status HTTP e o code de negócio separadamente. Um JSON malformado pode retornar HTTP `400` com uma mensagem de erro em texto simples, em vez da estrutura JSON mostrada abaixo. Verifique o `Content-Type` da resposta antes de interpretar o JSON. <Badge color="blue" size="sm">Complementado · api-22-F10</Badge> Uma resposta HTTP 200 também pode retornar um erro de negócio.

| `code` | Significado | Ação recomendada |
| --- | --- | --- |
| `200` | Requisição bem-sucedida | Leia data e avalie o resultado do processamento conforme o status de negócio deste endpoint. |
| `400` | Falha na requisição ou validação | Problema nos parâmetros. Verifique e corrija os parâmetros da requisição. Se `infraction_id` estiver ausente ou vazio, o code de negócio será `4000`. A mensagem em inglês é `Field infraction_id is required`. <Badge color="blue" size="sm">Complementado · api-22-F09</Badge> |
| `500` | Erro do sistema | Registre a resposta e confirme primeiro o resultado de negócio. |

Os exemplos ilustram a estrutura da resposta. Os valores de message e do status de negócio devem ser obtidos da resposta efetiva. Para outros erros de parâmetros, permissões e serviço, consulte [Catálogo de erros](/pt-br/api-reference/error-catalog). Esta seção não indica que o endpoint retorna apenas os três valores de code apresentados. <Badge color="orange" size="sm">Corrigido · api-22-F12</Badge>

<Tip>
Para testar este endpoint, envie o exemplo de requisição para a Base URL do Sandbox `https://ebanking-openapi-sandbox.pagsmile.com.br` com sua AK/SK de Sandbox. Assine cada requisição conforme descrito em [Ambientes e credenciais](/pt-br/environments-and-credentials#assinatura-de-requisições-à-api).
</Tip>
