## Behavior and handling

Query an actual incoming Pix payment transaction to check its status, amount, and identifiers. Details are available only after the transaction has completed. If the transaction is not found or has not completed, this endpoint returns business code `4003003` (Transaction detail not found). This response alone does not prove that the payment failed. <Badge color="blue" size="sm">Added · api-4-F01</Badge> Use event notifications and statement entries to confirm the credit to the account.

For QR code generation errors, missing notifications, or unconfirmed credits to the account, see [Error scenarios in the incoming payment module](/api-reference/payin/overview).

## Permissions and account ownership

Use `ACCOUNT` credentials for their bound account, or `USER` credentials with both `X-ISPB` and `X-Account-Number` for an authorized target account. With `ACCOUNT` credentials, omit both target headers or provide both with values matching the bound account. The target account must match a payer or payee account on the transaction; credentials do not grant access to unrelated transactions. <Badge color="blue" size="sm">Added · api-4-F03</Badge> Requests must follow [Environments & Credentials](/environments-and-credentials).

## Request parameters

<ParamField body="txn_id" type="string">
**Required:** At least one. Provide at least one of `txn_id` or `settlement_id`. If both are provided, `txn_id` takes precedence; `settlement_id` is not used to cross-check the transaction and is not tried if `txn_id` is not found. <Badge color="blue" size="sm">Added · api-4-F02</Badge>
</ParamField>

<ParamField body="settlement_id" type="string">
**Required:** At least one. Provide at least one of `txn_id` or `settlement_id`. If both are provided, `txn_id` takes precedence; `settlement_id` is not used to cross-check the transaction and is not tried if `txn_id` is not found. <Badge color="blue" size="sm">Added · api-4-F02</Badge>
</ParamField>

## Responses

View response examples by the business `code` in the JSON response. Check the HTTP status and business code separately. An HTTP 200 response can also return a business error. <Badge color="orange" size="sm">Corrected · api-4-F09</Badge>

| `code` | Meaning | Recommended action |
| --- | --- | --- |
| `200` | Request succeeded | Read data and determine the result using the business status defined for this endpoint. |
| `400` | Request or validation failed | Parameter issue. Check and correct the request parameters. |
| `500` | System error | Log the response and confirm the business result first. |

The examples illustrate this endpoint's response structure, including empty strings, null objects, and zero timestamps for fields that this endpoint does not populate. <Badge color="orange" size="sm">Corrected · api-4-F10</Badge> Use the actual response for message and business status values. See [Error Catalog](/api-reference/error-catalog) for other parameter, permission, and service errors. This section does not imply that the endpoint returns only these three code values. If both identifiers are empty, the business code is `4000` (Field `txn_id` or `settlement_id` is required), not the generic `400` example. Other relevant business codes include `4003003` (Transaction detail not found), `4004101` (Authorization is required) when the target account is not a transaction participant, `4003014` for a transaction-query processing error, and `501` when the service is temporarily unavailable. Use the actual response message and do not interpret a query-processing error as a failed payment. <Badge color="blue" size="sm">Added · api-4-F08</Badge>

## Sandbox access example

Use the actual response as the source of truth for transaction or resource information, processing status, and error information.

`X-Client-ID` uses the AK you enter. The timestamp, nonce, request body hash, and signature are generated automatically. SK is used only for local signing. It is not included in the request or stored. Previewing does not send a request. The access button submits a real request. If the result is unknown, query first. Requests are not retried automatically. Browser access must meet Sandbox CORS, IP, and credential requirements.

</Tip>
