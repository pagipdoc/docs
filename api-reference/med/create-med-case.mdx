## Behavior and handling

Create a MED case for the original Pix transaction to track dispute handling and funds recovery. Creating a case does not guarantee full recovery of funds.

### Case initiation requirements and original transaction linkage

Prepare the original Pix end-to-end ID, fraud situation, report description, and complaint time. Confirm that the original transaction is a Pix payment and that the original payer account is neither closing nor closed. The original payment must be retrievable with an amount and transaction ID. <Badge color="blue" size="sm">Added · api-17-F10</Badge> Use an original Pix payment belonging to the authorized account and verify that ownership before submitting. Account targeting does not itself verify ownership of the original transaction. The case remains linked to the original payment. <Badge color="orange" size="sm">Corrected · api-17-F05</Badge>

### Create MED case

Submit the case request with the applicable automatic return option, and save the case ID. Repeated submissions of the same request are not guaranteed to return the same case. If the result is unknown, check for an existing case before submitting again. <Badge color="blue" size="sm">Added · api-17-F11</Badge> `automatic_refund` specifies a return processing option. It does not guarantee automatic full recovery.

## Permissions and account ownership

ACCOUNT, or USER with both `X-ISPB` and `X-Account-Number` identifying an account owned by that user. PLATFORM credentials are not accepted. With ACCOUNT credentials, account headers may be omitted; if sent, both must be nonempty and match the credential-bound account. Requests must follow [Environments & Credentials](/environments-and-credentials). <Badge color="blue" size="sm">Added · api-17-F06</Badge>

## Request parameters

<ParamField body="end_to_end_id" type="string" required>
Original Pix end-to-end ID from `settlement_id` in an account statement entry with txn_status of 2
</ParamField>

<ParamField body="original_fraud_situation" type="integer" required>
**Required:** Yes; must be `1` to `6`. <Badge color="orange" size="sm">Corrected · api-17-F01</Badge> Original fraud situation enum. Accepted values: `1 SCAM`; `2 ACCOUNT_TAKEOVER`; `3 COERCION`; `4 SOCIAL_ENGINEERING`; `5 OTHER`; `6 UNKNOWN`. The enum value `0 UNSPECIFIED` is not accepted when creating a case. <Badge color="orange" size="sm">Corrected · api-17-F02</Badge>
</ParamField>

<ParamField body="report_details" type="string">
**Required:** No (not enforced at this layer). Dispute report description
</ParamField>

<ParamField body="complaint_create_time" type="integer">
**Required:** No (not enforced at this layer). Complaint creation time as a UTC Unix timestamp in milliseconds. If omitted, the value is `0` and no complaint time is sent. Positive values below `1000000000000` are treated as Unix seconds and converted to milliseconds; use milliseconds for new integrations. Nonpositive values do not send a complaint time. <Badge color="blue" size="sm">Added · api-17-F07</Badge>
</ParamField>

<ParamField body="automatic_refund" type="boolean">
**Required:** No (not enforced at this layer). Automatic return option. Defaults to `false` when omitted. `false` selects manual processing (`flow_type=2`); `true` selects automated processing (`flow_type=1`). The option is sent explicitly and does not guarantee full funds recovery. <Badge color="blue" size="sm">Added · api-17-F08</Badge>
</ParamField>

<Info>
**Parameter sources**

`end_to_end_id` comes from `data.statements[].settlement_id` in a successful response from [Get account statement](/api-reference/accounts/get-account-statement) (`/v3/statements`). Identify the original Pix payment being disputed and use its settlement ID. Confirm `payment_method=1` and the transaction details; do not choose an unrelated transaction merely because it has the largest amount. <Badge color="orange" size="sm">Corrected · api-17-F04</Badge>
</Info>
