## Behavior and handling

Query statement entries for the target account by time range to verify incoming payments, outgoing payments, refunds, and associated funds changes.

**Paginated queries**: Do not send cursor for the first page. For subsequent pages, use cursor and snapshot_timestamp returned by the previous page. Keep the account and filters unchanged. Stop when there is no valid cursor. Results are ordered by transaction initiation time in descending order, with transaction ID in descending order as the tie-breaker. Cursor pagination uses both values; do not construct a cursor from a timestamp alone. <Badge color="blue" size="sm">Added · api-24-F21</Badge>

**Retrieve missing statement entries**: To avoid missing late-arriving or backdated statement entries, we recommend querying part of the previously queried time range again in the next round. Deduplicate by transaction ID and check for changes to the records. Determine the lookback range according to your business agreement.

## Permissions and account ownership

Use `ACCOUNT` credentials for their bound account, or `USER` credentials with both `X-ISPB` and `X-Account-Number` to select an account owned by that user. With `ACCOUNT` credentials, omit both account headers or send both with values matching the bound account; they cannot select another account. `PLATFORM` credentials are not accepted. <Badge color="blue" size="sm">Added · api-24-F01</Badge> Requests must follow [Environments & Credentials](/environments-and-credentials).

## Request parameters

<ParamField body="page_size" type="integer">
Must be 1 to 100 if provided. Defaults to 20 if omitted. <Badge color="blue" size="sm">Added · api-24-F02</Badge>
</ParamField>

<ParamField body="txn_id" type="string">
**Required:** No (not enforced at this layer). Transaction ID
</ParamField>

<ParamField body="funds_type" type="integer">
**Required:** No (not enforced at this layer). Posting direction. Values: 0 `UNSPECIFIED`; 1 `CREDIT`; 2 `DEBIT`. Omitted or 0 selects both directions. `CREDIT` selects records where the target account is the payee and the underlying transaction is `COMPLETED`. `DEBIT` selects records where the target account is the payer, without a completed-only restriction. With no direction filter, the same completed-only restriction applies to incoming records, while outgoing records can have other statuses. Other integer values currently behave like `UNSPECIFIED` rather than being rejected. <Badge color="blue" size="sm">Added · api-24-F11</Badge>
</ParamField>

<ParamField body="start_date" type="integer" required>
Unix timestamp in milliseconds as an integer, nonzero and less than `end_date`. Use a positive value to apply an `initiated_at` lower bound, including the start boundary. Negative values pass the nonzero check but do not apply a lower time bound. <Badge color="orange" size="sm">Corrected · api-24-F22</Badge>
</ParamField>

<ParamField body="end_date" type="integer" required>
Unix timestamp in milliseconds as an integer, nonzero and greater than `start_date`. Use a positive value to apply an `initiated_at` upper bound, including the end boundary. Negative values pass the nonzero check but do not apply an end-date bound. The effective `snapshot_timestamp` upper bound still applies. <Badge color="orange" size="sm">Corrected · api-24-F23</Badge>
</ParamField>

<ParamField body="settlement_id" type="string">
**Required:** No (not enforced at this layer). Transaction settlement ID
</ParamField>

<ParamField body="transaction_type" type="integer">
If omitted or set to 0, no type filter is applied and the query includes `PAYMENT`, `REFUND`, and `DISPUTE`. Accepted values: 0 `UNSPECIFIED`; 1 `PAYMENT`; 2 `REFUND`; 6 `DISPUTE`. Values 3 `TRANSFER`, 4 `WITHDRAWAL`, 5 `DEPOSIT`, and other unsupported values are rejected with business code 400 and message `txn_type is invalid`. <Badge color="orange" size="sm">Corrected · api-24-F03</Badge>
</ParamField>

<ParamField body="snapshot_timestamp" type="integer">
Snapshot upper bound in Unix milliseconds. If omitted or set to 0 or a negative value, it defaults to the server's current Unix time in milliseconds. Reuse the returned value for subsequent pages. Records must have `initiated_at` less than the effective bound. This is not a database isolation snapshot. <Badge color="blue" size="sm">Added · api-24-F04</Badge>
</ParamField>

<ParamField body="cursor" type="object">
Use the cursor returned on the previous page. Keep the account, filters, and snapshot unchanged. Cursor pagination is applied only when `timestamp` is greater than 0 and `id` is nonempty; otherwise the cursor is ignored and the query starts without a cursor boundary. End the forward scan when no valid cursor is returned. <Badge color="blue" size="sm">Added · api-24-F05</Badge>
</ParamField>

<ParamField body="cursor.timestamp" type="integer">
↳ **Required:** Required when using a cursor. Unix timestamp in milliseconds as an integer greater than 0; use together with id
</ParamField>

<ParamField body="cursor.id" type="string">
↳ **Required:** Required when using a cursor. Cursor transaction ID, nonempty; use the returned value unchanged
</ParamField>

<ParamField body="cursor.direction" type="integer">
↳ Optional. Values: 0 `UNSPECIFIED`; 1 `FORWARD`; 2 `BACKWARD`. Omitted or 0 uses forward pagination. Only 2 selects backward pagination; other integer values currently use forward pagination rather than being rejected. Use 1 for forward scans and reuse the returned cursor unchanged. <Badge color="blue" size="sm">Added · api-24-F06</Badge>
</ParamField>

Use the actual response for message and business status values. <Badge color="orange" size="sm">Corrected · api-24-F15</Badge> See [Error Catalog](/api-reference/error-catalog) for other parameter, permission, and service errors. A failure to retrieve the statement records can return 4003014 with message `Unable to retrieve transactions at this time`; a transaction query service communication failure returns 501 with message `Service temporarily unavailable, please try again later`. Messages can be localized; use `code` for error classification. <Badge color="blue" size="sm">Added · api-24-F17</Badge>
