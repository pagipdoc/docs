## Behavior and handling

Create a VA managed account for a legal entity (CNPJ) under the MA identified by the USER credentials. A configured account opening fee is charged to the parent MA after the compliance submission succeeds and before the managed account is created. The parent bank account must be active and not undergoing closure, and must have sufficient available funds. A fee failure stops account creation. A matching retry reuses the confirmed fee payment rather than charging it again. <Badge color="blue" size="sm">Added · create-va-F26</Badge>

## Permissions and account ownership

Use the parent MA's USER credentials without a bank account header. The owning user must have the managed account feature enabled and exactly one valid MA with ACTIVE status. Requests must follow [Environments & Credentials](/environments-and-credentials).

## Responses

View response examples by the business `code` in the JSON response. Check the HTTP status and business code separately. An HTTP 200 response can also return a business error.

| `code` | Meaning | Recommended action |
| --- | --- | --- |
| `200` | Request succeeded<br />Only the structure is shown. The server response determines the actual fields and account opening status. | Read data and determine the result using the business status defined for this endpoint. |
| `400` | Request or validation failed | Parameter issue. Check and correct the request parameters. If `code` is `400` and the message states that the compliance submission was rejected and the fee was not charged, correct the request and use a new `reference_id`. If `code` is `504` and the message states that the compliance submission status could not be confirmed and the fee was not charged, retry the original request with the same `reference_id`. Do not treat either result as a completed account opening. <Badge color="blue" size="sm">Added · create-va-F27</Badge> |
| `500` | System error | Log the response and confirm the business result first. Account opening fee errors include: `4001999` for insufficient funds, requiring funding and a retry with the same `reference_id`; `4001013` for a reference reused for a different creation request, requiring a new reference; `4004004` for missing fee configuration and `400` for invalid fee configuration, requiring support; and `501` for temporarily unavailable configuration or an unconfirmed fee payment. For an unconfirmed fee payment, retry the original request with the same `reference_id` so a confirmed debit is not repeated. Use `message` to distinguish these conditions. <Badge color="blue" size="sm">Added · create-va-F28</Badge> |
