## Behavior and handling

Query refund details to link the original transaction, refund amount, and processing result for tracking and reconciliation.

### Links between original transactions, refunds, and statement entries

Save the original transaction's settlement ID, refund order ID, refund ID, settlement refund ID, amount, and status. Record the refund separately without overwriting the original transaction. Link the refund statement entry to the refund and original transaction to reconcile them. Use `parent_txn_id` and `parent_settlement_id` from the matching refund statement entry to identify the original transaction; this refund-details response does not populate `original_settlement_id`. <Badge color="blue" size="sm">Added · api-6-F10</Badge>

## Permissions and account ownership

ACCOUNT, or USER with both `X-ISPB` and `X-Account-Number` for an account owned by that USER. ACCOUNT credentials use their bound account; if account headers are sent, both must be nonempty and match that account. The target account must be the refund sender or recipient. The refund recipient (the original payer) can query only completed refunds; unfinished refunds are returned as business code `4003003` (Transaction detail not found). An account that is neither party receives business code `4004101` (Authorization is required). <Badge color="blue" size="sm">Added · api-6-F04</Badge> Requests must follow [Environments & Credentials](/environments-and-credentials).

## Request parameters

<ParamField body="refund_id" type="string">
**Required:** At least one. The `txn_id` from the statement entry for the refund you want to query, with `txn_type=2`; you must provide at least one of `refund_id` or `settlement_refund_id` <Badge color="orange" size="sm">Corrected · api-6-F01</Badge>
</ParamField>

<ParamField body="settlement_refund_id" type="string">
**Required:** At least one. The `settlement_id` from the same refund statement entry; you must provide at least one of `refund_id` or `settlement_refund_id`. If both are provided, `refund_id` takes precedence: `settlement_refund_id` is not used as a fallback and is not checked for a match. <Badge color="blue" size="sm">Added · api-6-F03</Badge>
</ParamField>

<Info>
**Parameter sources**

Find the record for the refund you want to query, with `txn_type=2`, in a successful [Get account statement](/api-reference/accounts/get-account-statement) (`/v3/statements`) response. <Badge color="orange" size="sm">Corrected · api-6-F02</Badge> Populate `refund_id` with `txn_id` and `settlement_refund_id` with `settlement_id` from the same record.
</Info>

View response examples by the business `code` in the JSON response. Check the HTTP status and business code separately. Malformed JSON or a JSON value with the wrong field type can return HTTP 400 with a text response rather than this JSON envelope; parse the business code only when the body is JSON. <Badge color="blue" size="sm">Added · api-6-F12</Badge> An HTTP 200 response can also return a business error. <Badge color="orange" size="sm">Corrected · api-6-F09</Badge>

| `code` | Meaning | Recommended action |
| --- | --- | --- |
| `200` | Request succeeded | Read data and determine the result using the business status defined for this endpoint. |
| `400` | Request or validation failed | Parameter issue. Check and correct the request parameters. |
| `500` | System error | Log the response and confirm the business result first. |

The examples illustrate the response structure. Use the actual response for message and business status values. See [Error Catalog](/api-reference/error-catalog) for other parameter, permission, and service errors. This section does not imply that the endpoint returns only these three code values. If both identifiers are empty, code `4000` is returned (Field refund_id or settlement_refund_id is required). If the refund is not found or is hidden from the recipient because it is not completed, code `4003003` is returned (Transaction detail not found). An unrelated target account receives code `4004101` (Authorization is required). A communication failure can return code `501`. <Badge color="blue" size="sm">Added · api-6-F11</Badge>
