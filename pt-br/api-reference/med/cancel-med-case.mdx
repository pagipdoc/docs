## Funcionamento e tratamento

Cancele um caso MED elegível para cancelamento. Antes de enviar a requisição, consulte os detalhes mais recentes e confirme can_cancel. Após o cancelamento, continue conferindo o caso e os resultados relativos aos recursos. Uma requisição bem-sucedida não significa necessariamente que o cancelamento definitivo foi concluído. Verifique o status retornado e consulte os detalhes mais recentes do caso antes de decidir se deve enviar outra requisição de cancelamento. <Badge color="blue" size="sm">Complementado · api-20-F03</Badge>

## Permissões e titularidade da conta

ACCOUNT, ou USER com `X-ISPB` e `X-Account-Number` para uma conta de titularidade desse USER. O caso MED deve pertencer à conta selecionada. Com credenciais ACCOUNT, omita os headers da conta-alvo ou envie ambos com os valores da conta vinculada às credenciais. <Badge color="blue" size="sm">Complementado · api-20-F01</Badge> As requisições devem seguir as orientações de [Ambientes e credenciais](/pt-br/environments-and-credentials).

## Parâmetros da requisição

<ParamField body="case_id" type="string" required>
ID do caso MED, obtido em `data.med_case.case_id` na resposta de sucesso da criação do caso MED
</ParamField>

<Info>
**Origem dos parâmetros**

O `case_id` é obtido em `data.med_case.case_id` na resposta de sucesso de [Criar caso MED](/pt-br/api-reference/med/create-med-case) (`/v3/med/create`).
</Info>

## Respostas

Consulte os exemplos de resposta pelo `code` de negócio no JSON. Verifique o status HTTP e o code de negócio separadamente. Uma resposta HTTP 200 também pode retornar um erro de negócio. <Badge color="orange" size="sm">Corrigido · api-20-F17</Badge>

| `code` | Significado | Ação recomendada |
| --- | --- | --- |
| `200` | Requisição bem-sucedida | Leia data e avalie o resultado do processamento conforme o status de negócio deste endpoint. |
| `400` | Falha na requisição ou validação | Problema nos parâmetros. Verifique e corrija os parâmetros da requisição. Um `case_id` ausente ou vazio retorna o `code` de negócio `4000`, com a mensagem em inglês `Field case_id is required`. Um caso que não é mais elegível para cancelamento retorna o `code` de negócio `400`; use a mensagem efetiva para identificar a causa. Essas falhas de validação usam HTTP `500`; verifique o `code` do JSON para distingui-las de erros do sistema. <Badge color="blue" size="sm">Complementado · api-20-F18</Badge> |
| `500` | Erro do sistema | Registre a resposta e confirme primeiro o resultado de negócio. |

O `code` de negócio `4004004` (HTTP `404`) indica que o caso MED não foi encontrado ou não pertence à conta selecionada. Verifique o `case_id` e o contexto da conta antes de tentar novamente. <Badge color="blue" size="sm">Complementado · api-20-F19</Badge>

Os exemplos ilustram a estrutura da resposta. Os valores de message e do status de negócio devem ser obtidos da resposta efetiva. Para outros erros de parâmetros, permissões e serviço, consulte [Catálogo de erros](/pt-br/api-reference/error-catalog). Esta seção não indica que o endpoint retorna apenas os três valores de code apresentados.

Um corpo JSON inválido ou um tipo de campo JSON incompatível pode retornar HTTP `400` com um erro de análise em texto simples, em vez da estrutura JSON de resposta apresentada abaixo. <Badge color="blue" size="sm">Complementado · api-20-F21</Badge>
