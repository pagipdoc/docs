## Behavior and handling

Create a PA payment account for an individual (CPF) or legal entity (CNPJ). Specify the MA it belongs to or a VA under that MA as the parent.

## Permissions and account ownership

Use the parent MA's USER credentials without a bank account header. The owning user must have the managed account feature enabled and exactly one valid MA with ACTIVE status. Requests must follow [Environments & Credentials](/environments-and-credentials).

You must submit linked_account for a PA in all compliance modes. The selected parent account must have `ACTIVE` status and meet the account ownership requirements. The configured account opening fee is charged in BRL to this direct parent account after the verification session is created and before the account creation request is accepted. CPF applicants use the KYC fee and CNPJ applicants use the KYB fee. The parent must have enough available funds. If the fee result is uncertain, retry with the same `reference_id`; do not create a new request solely because no response was received. <Badge color="blue" size="sm">Added · create-pa-F19</Badge>

The selected parent account must have `ACTIVE` status and meet the account ownership requirements. The parent’s bound bank account must also be `ACTIVE` and must not have closure in progress. A VA parent and its owning MA must both have valid active bank account bindings. <Badge color="blue" size="sm">Added · create-pa-F22</Badge>

## Request parameters

PA supports the following compliance information submission methods. Select a submission method and account applicant to view the parameters and examples.

**Account onboarding mode**

- mode1: Hosted link (customer provides additional information through the review link)
- mode2: API submission (submit detailed information in the request)

**Account applicant**

- Legal entity (CNPJ)
- Individual (CPF)

The enabled configuration determines which applicant types are eligible. Client reference data is an optional supplement for API submission. The PA parent account is not an account onboarding mode and is always required.

<ParamField body="reference_id" type="string" required>
Must not be empty after trimming leading and trailing whitespace. Generate and save the value; the code does not enforce UUID format. Keep the value unchanged for technical retries of the same account opening request. For a retry, keep the owning USER, `linked_account`, `model`, `compliance_mode`, applicant document type and tax ID, `trading_name`, and `notification_email` unchanged. Reusing a `reference_id` for incompatible account details can fail; a `reference_id` is not an update operation. <Badge color="blue" size="sm">Added · create-pa-F17</Badge>
</ParamField>

<ParamField body="model" type="integer" required>
Fixed at 3 (PA)
</ParamField>

<ParamField body="compliance_mode" type="integer" required>

</ParamField>
