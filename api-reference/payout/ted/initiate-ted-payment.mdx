## Behavior and handling

Initiate a TED payment using the payee's bank account details. Processing is subject to the enabled channels and bank rules. TED submission follows the Brazil banking calendar in America/Sao_Paulo. Submission stops 65 minutes before an active banking window closes. Outside the submission window, an accepted payment is scheduled for the next active window; do not submit it again. <Badge color="blue" size="sm">Added · api-15-F20</Badge>

The payer account must have sending payments enabled. TED payments consume the same configured payment quota as Pix payments for that account and payee document type. Query the payment result after submission. <Badge color="blue" size="sm">Added · api-15-F21</Badge>

If the request result is unknown, check the original transaction as described in [Error scenarios in the outgoing payment module](/api-reference/payout/overview). Do not resend the request directly.

## Permissions and account ownership

Use `ACCOUNT` credentials for the account bound to those credentials, or `USER` credentials with both `X-ISPB` and `X-Account-Number` for an active account owned by that `USER` within its valid account hierarchy. `PLATFORM` credentials are not allowed. With `ACCOUNT` credentials, omit both account headers or send both with values matching the bound account. <Badge color="blue" size="sm">Added · api-15-F13</Badge> Requests must follow [Environments & Credentials](/environments-and-credentials).

## Request parameters

<ParamField body="payee" type="object" required>
Payee identity and bank account information
</ParamField>

<ParamField body="payee.name" type="string" required>
↳ Payee name. Decomposable Latin accents are removed before TED processing. After normalization, only printable ASCII characters are accepted; control characters, emoji, and unsupported non-ASCII characters are rejected. <Badge color="blue" size="sm">Added · api-15-F11</Badge>
</ParamField>

<ParamField body="payee.document_id" type="string" required>
↳ Payee document ID, consistent with the document type and the actual payee account
</ParamField>

<ParamField body="payee.document_type" type="integer">
↳ **Required:** Yes. <Badge color="orange" size="sm">Corrected · api-15-F01</Badge> Payee document type. Accepted values: `1 CPF`; `2 CNPJ`. Omission, `0 UNSPECIFIED`, and other values are rejected. <Badge color="orange" size="sm">Corrected · api-15-F02</Badge>
</ParamField>

<ParamField body="payee.bank_account" type="string" required>
↳ Payee account number; digits only, with no spaces, punctuation, or check-digit separators. Preserve leading zeros. <Badge color="blue" size="sm">Added · api-15-F08</Badge>
</ParamField>

<ParamField body="payee.bank_account_type" type="integer">
↳ **Required:** Yes. <Badge color="orange" size="sm">Corrected · api-15-F03</Badge> Payee bank account type. Accepted values: `1 CHECKING`; `2 SALARY`; `3 SAVINGS`; `4 PAYMENT`. Omission, `0 UNSPECIFIED`, `5 TRANSCTIONAL_PI`, `6 GUARANTEED`, `7 DEPOSIT`, and other values are rejected. <Badge color="orange" size="sm">Corrected · api-15-F04</Badge>
</ParamField>

<ParamField body="payee.bank_branch" type="string" required>
↳ Payee bank branch code; digits only, with no spaces or punctuation. Preserve leading zeros. Required even when `payee.bank_account_type` is `4 PAYMENT`. <Badge color="blue" size="sm">Added · api-15-F09</Badge>
</ParamField>

<ParamField body="payee.bank_code" type="string" required>
↳ Payee bank ISPB string; preserve leading zeros. All whitespace is removed, letters are converted to uppercase, and values shorter than 8 characters are padded with leading zeros. After normalization, provide an actual, valid 8-digit ISPB; letters are not accepted for payment processing. The payee ISPB must differ from the payer account ISPB; TED payments to the same bank are rejected. <Badge color="blue" size="sm">Added · api-15-F10</Badge>
</ParamField>

<ParamField body="payee.bank_name" type="string">
↳ **Required:** No (ignored). <Badge color="orange" size="sm">Corrected · api-15-F05</Badge> Optional; ignored by this endpoint. The payee bank is identified and validated using `payee.bank_code`. <Badge color="orange" size="sm">Corrected · api-15-F06</Badge>
</ParamField>

<ParamField body="amount" type="string" required>
Decimal amount string; the value must be greater than `0` and exactly representable with at most two decimal places (for example, `10.00`). Extra trailing zeros, such as `10.000`, are accepted. `0`, negative numbers, and `10.555` are not accepted. <Badge color="orange" size="sm">Corrected · api-15-F07</Badge>
</ParamField>

<ParamField body="currency" type="string">
**Required:** No (not enforced at this layer). Currency; bank account payments are processed in BRL in this version
</ParamField>

<ParamField body="memo" type="string">
**Required:** No (not enforced at this layer). Optional transaction note. Decomposable Latin accents are removed before TED processing. After normalization, only printable ASCII characters are accepted; line breaks, other control characters, emoji, and unsupported non-ASCII characters are rejected. <Badge color="blue" size="sm">Added · api-15-F12</Badge>
</ParamField>

<ParamField body="merchant_order_id" type="string" required>
Merchant order ID; only English letters, digits, hyphens, and underscores are allowed. The first six characters must be a valid `YYMMDD` UTC date. The date must overlap the window within ±1 hour of the current UTC time. If the result is unknown, query the original operation first. Do not blindly resubmit with a new ID. Use an order ID unique across accounts. Accepted order IDs are retained for duplicate protection for 48 hours. A repeated submission with a retained ID is rejected with code `4001013`; it does not return the original successful response. <Badge color="blue" size="sm">Added · api-15-F19</Badge>
</ParamField>

<ParamField body="purpose" type="integer">
**Required:** Not supported. This version does not use this field to control the payment purpose. Values: 0 UNSPECIFIED; 1 TAX; 2 PUBLIC_UTILITY; 3 DIVIDENDS; 4 SALARY; 5 SUPPLIER; 6 PROFESSIONAL_FEES; 7 RENT_CONDOMINIUM; 8 TRADE_BILLS; 9 SCHOOL_TUITION; 10 ACCOUNT_CREDIT; 11 BROKERAGE; 12 REGISTRY_BANK_SLIP; 13 COLLECTION_FEES; 14 PROTEST_REGISTRY; 15 CARD_OPERATOR_SETTLEMENT
</ParamField>
