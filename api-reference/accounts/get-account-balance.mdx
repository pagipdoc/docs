## Behavior and handling

Use ACCOUNT-level credentials to query information, balances, frozen amounts, and associated configuration for the account bound to those credentials.

If the balance snapshot query fails, the outer code can still be 200, and amounts fall back to 0. The current response has no fallback indicator, so a single response cannot distinguish a true zero balance from a fallback value. Query again and cross-check the account's transaction details and statement entries. If the results still do not match, keep a record of the account details, query time, and masked response, and contact integration support to investigate.

## Permissions and account ownership

Use the account's ACCOUNT AK/SK. By default, the query targets the bound account, so no account headers are needed. If you provide either `X-ISPB` or `X-Account-Number`, you must provide both, and both must match the bound account.

The request body is `{}`. Account selection is not passed through the `account_number` field in the request body. For request signing, see [Environments & Credentials](/environments-and-credentials).
