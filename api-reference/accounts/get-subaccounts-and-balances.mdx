## Behavior and handling

Use USER-level credentials to query a specified subaccount's information, balance, frozen amount, and associated configuration within your authorization scope. Query only one target account at a time.

If the balance snapshot query fails, the outer code can still be 200, and amounts fall back to 0. The current response has no fallback indicator, so a single response cannot distinguish a true zero balance from a fallback value. Query again and cross-check the account's transaction details and statement entries. If the results still do not match, keep a record of the account details, query time, and masked response, and contact integration support to investigate.

## Permissions and account ownership

Use USER AK/SK. You must include both the `X-ISPB` and `X-Account-Number` headers for the target subaccount. The server validates the target account's status and USER ownership. You cannot query other users' accounts.

The request body is `{}`. Account selection is not passed through the `account_number` field in the request body. For request signing, see [Environments & Credentials](/environments-and-credentials).

<ParamField header="X-Client-ID" type="string">

</ParamField>

<ParamField header="X-ISPB" type="string">
Required. The target subaccount's ISPB. Preserve leading zeros
</ParamField>

<ParamField header="X-Account-Number" type="string">
Required. The target subaccount's account number. Pass it as a string and preserve leading zeros
</ParamField>

<ParamField body="No fields" type="string">
`{}`
</ParamField>

## cURL request example

Use your actual USER AK/SK to generate the timestamp, nonce, body SHA-256 hash, and signature before sending the request. Do not include the SK in the request. Both target account headers must also be included in signing.
